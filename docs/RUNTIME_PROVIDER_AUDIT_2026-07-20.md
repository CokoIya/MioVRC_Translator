# Runtime, Provider Compatibility, and Qwen TTS Audit

Audit date: 2026-07-20

Primary runtime evidence: the supplied player log, summarized without user text, credentials, device names, process identifiers, or other personal data.

Code basis: the current worktree, including the provider, latency, OSC, manual-translation, lifecycle, and TTS fixes prepared for this update.

## Evidence boundary

The supplied log contains 10,003 records from 2026-06-17 through 2026-07-19. Runtime observations and code/test verification are kept separate in this report:

- Live translation-provider evidence is limited to Qwen-MT through a DashScope OpenAI-compatible endpoint.
- Live TTS evidence is limited to Edge TTS.
- The log has no live GPT/OpenAI, Claude/Anthropic, Grok/xAI, compatible-relay, or Qwen API TTS request samples.
- Compatibility claims for paths without live samples are therefore code- and regression-test-backed, not production-endpoint certification.

## Executive findings

- Modern translation calls recorded 837 successes and 45 failures. Forty failures were TLS/connect timeouts, four were response-header/read timeouts, and one was a protocol failure. The dominant incident is transport establishment, not local recorder queue loss.
- The realtime scheduler recorded 956 completions. End-to-end latency was 718 ms at p50, 6.391 s at p95, and 8.719 s maximum. Strict ordering correctly preserved sentence order, but a slow earlier item propagated delay; observed reorder wait reached 4.344 s.
- OSC delivery time was absent from earlier pipeline totals. Its local queue wait reached 2.328 s and rate-limit wait reached 0.8 s, producing 3.125 s total downstream delay in the worst observed case.
- Two provider content-inspection rejections were presented too generically. They now map to a localized safety category. User-facing messages contain localized recovery copy, while runtime diagnostics expose only bounded exception type/status and allowlisted provider-code metadata; neither path emits raw provider prose or tracebacks.
- The player log contains 1,825 third-party `httpx` request records with the complete DashScope request path. A custom relay could place tenant identifiers or bearer-like routing tokens in the same path. Mio now suppresses `httpx`, `httpcore`, `urllib3`, OpenAI SDK, and Anthropic SDK transport records at every application log handler; Mio's own path-free origin, opaque endpoint ID, timing, and safe error summaries remain available.
- The microphone watchdog emitted 34 `audio_present_but_no_segment` diagnostics and performed 22 sustained-digital-silence restarts. Recorder diagnostics reported no dropped or stale frames, so the evidence points to capture-stream recovery rather than recorder queue saturation.
- Four Qt shutdown requests lacked matching cleanup-completion records; two earlier legacy-UI shutdown sequences did include both request and completion. Shutdown completion now remains pending until ASR cleanup, application and settings-test TTS synthesis/playback/engine release, manager/request-close/engine-close handoffs, Qwen DNS resolver release, manual translation workers and their provider-cleanup threads, and supervised provider work all report quiescence; only then is the terminal cleanup event emitted.
- The updater emitted 284 warnings: 168 per-source failures, 84 attempt failures, 28 exhausted checks, three explicit retry notices, and one terminal check failure. Missing-signature verification and transient transport symptoms overlap within the aggregated source failures. Existing permanent-versus-transient retry handling was preserved.

Shared GPT, Claude, and Grok controls in the current worktree include:

- Credential admission rejects missing, undecryptable, oversized, or control-character-bearing keys. Provider acceptance is determined by a connection test or a real request.
- Custom request headers are JSON-object validated, bounded, protected at rest, and reject hop-by-hop, host, content-length, proxy-authorization, and control-character injection.
- Standard environment/system proxies are honored by the persistent HTTP clients. A relay itself is configured through Base URL; there is no separate per-provider proxy-credential field.
- Connect, pool, read, write, and wall timeout settings are independently bounded. One supervised wall deadline covers streaming, non-streaming, SDK-internal blocking, compatibility-parameter fallback, and configured provider fallback chains. Expiry synchronously retires the client, moves potentially blocking SDK cleanup off the deadline thread, and returns a stable wall-timeout failure at approximately the configured deadline, subject to normal scheduler overhead. Registered call and cleanup threads, including the brief pending-start state, remain visible to terminal shutdown monitoring until they exit.
- SDK retry count remains configurable for non-realtime requests. Realtime provider clones force SDK retries to zero and rely on bounded client rotation/fallback so retries cannot amplify ordered-pipeline latency. Cancellation closes and rotates the active client where destructive cancellation is required, while generation checks suppress late results.
- Authentication, rate-limit/quota, unsupported model/parameter, invalid endpoint, network, provider, safety, cancellation, empty-response, configuration, and dependency failures use centralized localized categories.
- Provider and scheduler diagnostics log only the path-free endpoint origin, an opaque endpoint identifier, bounded timing values, bounded exception type/status, and allowlisted provider-code metadata. Realtime translation failures use the same safe summary rather than rendering exception messages or tracebacks. Third-party HTTP/SDK transport records are suppressed at the application handlers. Custom relay path tokens, raw provider prose or bodies, credentials, headers, prompts, and translated text are excluded.
- Realtime translation, reverse translation, manual translation, ASR rewrite, and typed-text rewrite use the same provider factories and transports. Sequential manual requests reuse a healthy client; overlapping work is isolated; timed-out clients are detached and rotated. Realtime and manual timeout cleanup is supervised asynchronously so a blocking SDK close cannot hold the ordered worker or Qt thread.
- Realtime scheduler bounds ingress and provider queues, preserves strict sentence order, expires stale queued work, reports health/backlog, and cancels outstanding generations during stop or reconfiguration.

## Qwen TTS path audit

1. **Admission and queueing.** `src/core/tts_service.py` forwards request context to `src/tts/manager.py`. Text is validated before admission. The synthesis queue and total outstanding set are bounded; saturation drops the newest request with a stable localization token rather than blocking the UI. Queue depth, high-water mark, admission time, and local queue wait are logged.
2. **Text and language preparation.** Correction-dictionary processing belongs to the upstream ASR pipeline and is not applied a second time by Qwen TTS. The TTS engine receives the selected output text, validates text/voice, applies the configured language hint, and otherwise performs conservative language-type detection. Ambiguous Latin text uses automatic detection; a target-language hint resolves ambiguous Japanese text. Style instructions are sent only for models that support them.
3. **Cold start and connection reuse.** Prewarm runs on a synthesis worker. Each worker owns a reusable session through a thread-local session pool, with bounded connection pools and disabled hidden adapter retries. Diagnostics distinguish first use from warm-session reuse for both synthesis and audio download.
4. **Request construction.** Qwen TTS posts a bearer-authenticated JSON request to the DashScope multimodal-generation path, preserving the selected model and voice. API keys are never sent over public plaintext HTTP. Unsafe Base URLs, credentials in URLs, and ambiguous hosts are rejected; loopback HTTP remains available for local compatibility. API POST redirects are rejected. Audio-download redirects are bounded, and every destination is revalidated and pinned.
5. **Timeout and cancellation.** Connect and read timeouts are separate. A wall-clock deadline is propagated into request and body-read checks, so a trickling body cannot run indefinitely. Shutdown sets a close event, closes sessions, and causes new or continuing deadline-aware work to terminate with a structured cancellation outcome. Non-cancellable `getaddrinfo` work is registered before thread start, retains its resolver slot and engine until it exits, and is counted in manager quiescence; construction/start failure releases the slot immediately.
6. **Retry policy.** Only narrowly classified transient transport failures are retried, using a fresh session and bounded backoff. Backoff waits on the engine close event and is capped by the remaining absolute deadline, so shutdown interrupts it immediately and it cannot extend the wall timeout. Certificate validation, authentication, and other client errors are not retried. The non-idempotent synthesis POST is retried only before response-body processing begins. The idempotent audio download may restart from the beginning after a transient failure without resubmitting synthesis.
7. **Response and download safety.** API responses are streamed with hard size limits. Inline audio is format-checked and base64 decoding is bounded. Remote audio URLs reject credentials, fragments, private/link-local destinations, unsafe public HTTP, and invalid redirects. DNS is resolved under the remaining wall deadline and the validated address is pinned for the download while preserving the original Host header and TLS SNI, preventing a second DNS lookup from rebinding to a private address. Provider-supplied audio downloads intentionally bypass environment proxies so the validated destination cannot be replaced by proxy routing.
8. **Decode, buffering, and playback.** Synthesis workers predecode audio so decode/conversion can overlap playback of the preceding sentence. The manager validates supported containers, converts to contiguous float PCM, resamples with the preferred high-quality path when available, buffers with a short zeroed tail, and drives local and virtual-audio-device output streams with a duration-scaled playback watchdog.
9. **Rapid sentences and strict order.** Cloud engines default to two synthesis workers. Later sentences may synthesize while earlier audio plays, but a dedicated playback worker emits results in sequence order. A stalled ordered head expires once at its wall limit so later completed Qwen tasks can proceed. Generation checks discard any late stale result. Retired-worker quarantine is bounded, and synthesis capacity is restored when an old stalled worker finally exits; replacement thread-start failure rolls back bookkeeping without killing playback or creating phantom capacity.
10. **Failure and shutdown resource release.** Every terminal path releases the outstanding identity before callback delivery. Queue clear advances the generation and cancels queued, completed, and active identities. Stop wakes workers without blocking on a full queue, closes playback streams, releases audio buffers and caches, closes per-thread sessions, and defers final engine destruction until blocked synthesis workers and resolver work exit. Manager-close, deferred `request_close`, and engine-close handoffs all count as non-quiescent. An overlapping or repeated `close()` cannot detach the engine mid-handoff or report terminal quiescence while the first closer is still completing stop and resource release. `TtsService` publishes a manager only after availability and start succeed; unavailable and partial-start instances receive bounded cleanup. A settings-window TTS test registers its detached manager with the main lifecycle monitor before asynchronous close starts; thread-start failure uses a bounded inline handoff rather than losing the detached manager.

The manager-level short duplicate window prevents accidental immediate echo, while later repeated playback can use the bounded audio cache. Repeated start/stop, replacement managers, full queues, synthesis failures, playback failures, virtual-device recovery, stalled-head recovery, and stale-generation suppression all have focused regression coverage.

## Lifecycle, ordering, and recovery conclusions

- Strict ordering is intentionally preserved for realtime translation, OSC chatbox delivery, and TTS playback. The update adds visibility and bounded recovery rather than allowing out-of-order sentences.
- Multi-target realtime and manual requests aggregate transport, provider, first-token, full-response, parse, and post-processing diagnostics across every provider call instead of exposing only the final target's metrics. Failed rewrites and translations copy their last safe timing snapshot before the client is retired.
- Scheduler stop cancels UI delivery before joining workers, clears translation context, invalidates source generations, and drains TTS/OSC work for the old session.
- Provider clients are long-lived during healthy sequential work and closed on failure, manual timeout, runtime replacement, update handoff, or shutdown.
- Provider fallback access is locked and retirement-aware: a timed-out chain cannot create or retain a late fallback after shutdown takes its client snapshot. Logical provider attempts and underlying HTTP attempts are reported separately.
- TTS callbacks observe an already-released pipeline slot. Failed synthesis never reaches playback/device routing. Failed or cancelled work releases pipeline identities immediately. Resources owned by a still-blocked synthesis worker or DNS resolver are retired and released when that work exits; final engine destruction remains deferred until then. Settings-test managers use the same deferred-quiescence monitor as the main TTS manager. Quiescence remains false throughout manager-close, request-close, and engine-close handoffs, preventing premature terminal-cleanup reporting and double destruction during concurrent close calls.
- Manual translation invalidation detaches clients immediately, but cancel/close work is performed only by registered cleanup threads. Pending-start, active, emergency, and retryable cleanup all keep controller quiescence false. Retired typed-rewrite and translation clients are rotated before reuse, and overlapping requests cache the new isolated client while the older in-flight client is retired after its lease ends.
- The supplied log proves that microphone digital-silence recovery activated and that recorder queues did not drop frames. It does not prove a specific hardware or driver root cause.
- The supplied log does not prove successful final cleanup for the four Qt shutdown sequences without terminal records. The corrected code now makes the terminal lifecycle record contingent on verified ASR, TTS, manual-worker, and registered provider call/cleanup quiescence, and regression tests hold that record back until delayed resources finish.

## Localization audit

The supported UI languages are Simplified Chinese, English, Japanese, Russian, and Korean.

- Provider names, provider hints, Base URL/model guidance, credential prompts, streaming controls, custom-header controls, granular timeout labels, connection-test messages, and validation warnings are routed through localized settings catalogs.
- Translation errors use localized provider labels and stable categories. Raw provider prose does not appear in short, inline, or detailed UI messages for authentication, quota, endpoint, model, provider, cancellation, or safety failures.
- Qwen TTS passes stable error tokens from worker threads. The UI maps authentication, network, timeout, rate limit, unsupported model, invalid endpoint, busy/saturation, playback, provider, invalid-input, and unavailable outcomes to localized recovery messages.
- Queue-expiry, queue-full, OSC admission, ASR temporary failure, and credential failure notifications use UI copy keys. Developer diagnostics retain stable English field names for machine parsing but are not displayed as untranslated UI text.
- Localization validation covers missing keys, empty values, and placeholder mismatches across all five languages.

## Residual evidence gaps

- A controlled smoke matrix against official OpenAI, Anthropic, and xAI endpoints plus representative compatible relays is still required for live certification of credentials, proxy behavior, provider-specific errors, streaming cadence, and real connection reuse.
- A controlled Qwen TTS smoke run is still required to establish cold-start, first-audio, full-response, download, decode, playback, and shutdown baselines against the real service.

- A live shutdown smoke run should confirm the new terminal cleanup event on a packaged build, especially while cancelling a deliberately delayed provider or TTS request.
